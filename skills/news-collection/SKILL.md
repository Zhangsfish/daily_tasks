# 公开新闻采集与核查规则

本 skill 是公开的采集准则，执行代码为 `scripts/collect.py`。目标是给读者一组可以追溯的报道入口，而不是自动改写新闻事实。

## 来源选择

- 全球新闻：BBC News World、The Guardian World、NPR World。
- AI 动态：TechCrunch AI、The Verge AI、VentureBeat AI。
- 使用各媒体公开 RSS/Atom；只接受其对应媒体域名的 HTTPS 原文链接。媒体之间须是不同出版方，不能把同一媒体的转载当作第二来源。
- 这组来源是可审查的初始名单，并不代表观点、地域覆盖或新闻质量完全均衡。新增来源时，先核对其编辑责任、原始链接稳定性、发布日期、访问条款，再修改代码与测试。

## 入选和去重

1. 只考虑带明确发布时间、距采集时刻不超过 48 小时的条目；排除未来日期、空标题、非 HTTPS 或跳出白名单域名的链接。多主题通讯、汇总稿与标题明显拼接多个事件的条目也排除，避免第二来源只印证其中一部分。
2. 找另一家独立媒体在 36 小时内发布的报道。标题须至少共享 3 个非通用英文词，词集合 Jaccard 相似度至少 0.28，完整标题相似度至少 0.45。这是主题匹配门槛，不是事实真伪的数学证明；门槛依据托管环境的实际 RSS 分布调整。
3. 打开两篇原文，确认 HTTPS 仍在批准的媒体域名、响应为 HTML，且页面标题与 RSS 标题共享至少 2 个关键词。访问失败、标题不符或跳转到外域即排除。
4. 同一原文 URL 当天最多入选一次；每栏最多 4 条，按发布时间优先。只显示第一来源原题，并展示第二来源链接与其发布时间。没有模型生成的概述或未经来源支持的推断。
5. 两栏都至少有一条通过核查的报道，才生成当日快照。任何一栏证据不足或采集失败，命令以非零状态退出，不写新归档、不提交、不部署。读者继续看到上一次已核查内容及其日期。

## 不确定性与纠错

标题交叉印证只能证明两家来源都报道了相似主题，不能自动证实正文每个数字、引述、因果或后续变化。因此每条均写明：**两家独立来源的标题与时间相互印证；自动核查未逐项验证正文细节，事件仍可能变化。** 不得将这个自动门槛描述为完整的人工事实核查。

如发现误配、更新或撤稿，人工检查原文和第二来源；在仓库中修正或撤下对应归档并保留 Git 提交记录。不要为了填满版面降低核查门槛。采集器失败时先查看 Actions 日志中的来源错误，不要手动补写未经验证的内容。

## 执行

在仓库根目录运行 `python3 -m unittest discover -s tests -v`，再运行 `python3 scripts/collect.py --dry-run`。通过后运行 `python3 scripts/collect.py` 写入快照。GitHub Actions 工作流负责每日自动执行、提交和 Pages 部署。
